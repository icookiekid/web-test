🔐 Firebase 설정 가이드

Authentication, 승인 도메인, Firestore Rules, web-test 전용 저장 경로를 확인하는 초보자용 문서입니다.

이 문서의 목적

이 블로그는 기존 블로그와 섞이지 않도록 web-test 전용 저장 위치만 사용합니다. Firebase에서 로그인한 사람의 UID 아래에 site 문서를 만들고, 그 안에 블로그 데이터를 저장합니다.

반드시 유지할 저장 경로
users / 로그인한 사용자 UID / sites / web-test
주의: 기존 블로그에서 쓰던 저장 경로와 섞으면 안 됩니다. 이 파일은 web-test 전용으로 sites / web-test 문서만 사용해야 합니다.

1단계. Firebase Authentication 확인

  1. Firebase 콘솔에서 프로젝트 Icookiekid-GPT를 엽니다.
  2. 왼쪽 메뉴에서 Authentication을 누릅니다.
  3. Sign-in method에서 Email/Password가 사용 설정되어 있는지 확인합니다.
  4. 이 블로그는 별도 관리자 비밀번호를 쓰지 않고 Firebase 이메일/비밀번호 로그인만 사용합니다.

2단계. Authorized domains 확인

GitHub Pages 주소에서 Firebase 로그인이 되려면 승인된 도메인에 아래 주소가 있어야 합니다.

icookiekid.github.io

이미 등록되어 있으면 그대로 두시면 됩니다.

3단계. Firestore Rules 확인

Firestore 규칙은 로그인한 사용자 본인의 UID 아래 데이터만 읽고 쓸 수 있게 되어 있어야 합니다.

rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { match /users/{userId}/{document=**} { allow read, write: if request.auth != null && request.auth.uid == userId; } } }

이 규칙은 로그인한 사용자 UID와 경로의 userId가 같을 때만 저장과 불러오기를 허용합니다.

4단계. 저장 위치 확인

  1. 블로그 상단의 ☁️ 동기화 메뉴로 이동합니다.
  2. Firebase 이메일/비밀번호로 로그인합니다.
  3. Firebase에 저장을 누릅니다.
  4. Firebase 콘솔 Firestore Database에서 아래 구조를 확인합니다.
users └─ 내 UID └─ sites └─ web-test
정상이라면 web-test 문서 안에 payload, ownerUid, ownerEmail, updatedAt 같은 값이 보입니다.
